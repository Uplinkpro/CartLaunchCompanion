# Cart Launch Companion 2.0 JSON Specification

## Goals

The Version 2 format must be:

- Human-readable
- Grouped by purpose
- Complete when generated
- Cross-platform
- Schema-backed
- Easy to edit in VS Code
- Compatible with relative portable paths
- Importable from Version 1

JSON files generated by Cart Launch Companion include all supported options, including blank options.

## Root structure

```json
{
  "$schema": "../../Schemas/game.schema.json",
  "formatVersion": 2,
  "game": {},
  "artwork": {},
  "launch": {},
  "behavior": {},
  "notes": ""
}
```

## Platform selection

`launch.preferredPlatform` accepts:

- `automatic`
- `windows`
- `linux`

`automatic` selects the configuration for the running operating system.

## Artwork terminology

Version 2 uses:

- `cover` for portrait library artwork
- `background` for the wide metadata-page background
- `logo` for optional game logo artwork

## Compatibility badges

Optional game information fields may add compact compatibility badges to the
Metadata view:

- `steamDeckCompatibility`: `unknown`, `verified`, `playable`, or `unsupported`
- `gamepadSupport`: `unknown`, `full`, `partial`, or `unsupported`

`unknown` badges stay hidden. Steam metadata may fill full or partial gamepad
support when the configuration has not supplied an override. Steam Deck status
remains configuration-driven because Valve does not publish it through the
regular store metadata response.
- `icon` for optional compact icon artwork
- `trailer` for local video

Steam background metadata should prefer library hero/background artwork rather than the small storefront header.

## Compatibility

Version 1 JSON is read through a compatibility importer.

The importer should:

1. Read the Version 1 file without modifying it.
2. Map known fields into a Version 2 model.
3. Report unmapped fields.
4. Allow the user to save a Version 2 copy later.
5. Never destroy the original automatically.

## Validation

Validation has two levels:

### Schema validation

Used by editors for:

- Allowed values
- Property descriptions
- Required fields
- Type validation
- Autocomplete

### Runtime validation

Used by the application for:

- Missing launch target
- Missing files
- Unsupported platform
- Invalid process settings
- Conflicting launch options
- Unsafe or malformed paths
